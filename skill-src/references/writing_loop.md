# 写作循环：指令行为定义

## `/write` — 推进剧情

### 执行前准备（必须完成，按顺序）

**第0步：确定当前段落编号（每次 /write 必须先做这一步）**

检查 `drafts/chXX_draft.md` 是否存在：
- 文件不存在 → 当前为**第1段**，本次 /write 将创建文件
- 文件存在，内容只有1段（约900字）→ 当前为**第2段**
- 文件存在，内容有2段（约1800字）→ 当前为**第3段（最终段）**

判断完成后，在内心确认："本次我将写第X/3段"，并以此决定本次输出的结束行为（暂停 or 封存协议）。

```
0. 读取 meta/project_info.md，获取 genre 和 language 字段
   - genre: mystery → 执行推理版逻辑（以下步骤1-6不变）
   - genre: romance → 执行爱情版逻辑（步骤2替换，步骤3字段调整，见下方）
   - language: zh / en → 确认本次 /write 输出语言

1. 读取 meta/style_guide.md（仅加载"绝对禁止"和"样板句式"两节）

2. [mystery] 读取 meta/truth.md（提醒自己不能泄露的信息）
   [romance] 读取 meta/relationship_arc.md（关系弧线文档，了解当前章节的情感状态目标）

3. 读取 meta/characters.md（本章出场角色）
   ⚠️ 首次出场角色只加载以下字段：
   - 出场前读者已知信息
   - 出场引入方式
   - 身份（仅职业/社会角色）
   [mystery] 完整档案（性格、动机、隐瞒的事）须在该角色二次出场后才解锁。
   [romance] 完整档案（性格、情感盲区、情感起点）须在该角色二次出场后才解锁。

4. [mystery] 读取 meta/clues.md（已投放 / 待投放线索）
   [romance] 读取 meta/romance_clues.md（情感信号投放状态）

5. 若 drafts/chXX_draft.md 存在：读取全文（衔接 + 确认段落数）；否则读取上一章 chXX.md 最后500字

6. 读取 meta/outline.md 中本章的计划节点
```

### 写作前行为预检

[mystery] 在涉及凶杀或高风险对抗的场景前，先用一句话回答：
"[受害者]此时的信息量是[X]，他/她的求生本能和处事逻辑，会让他/她做出什么行为？"
如果计划中的剧情与这个答案冲突，必须调整触发条件（让场景在更高的张力点爆发），而不是降低人物智识。

[romance] 在涉及情感决定性转折（表白/分离/和解）的场景前，先用一句话回答：
"[角色名]此时对对方的真实认知是[X]，他/她的情感逻辑和自我保护机制，会让他/她做出什么行为？"
如果计划中的剧情要求角色做出与其情感逻辑不符的行为，必须先补写情感积累，让转变有迹可循。

### 写作规范

**字数与节奏**：每章目标约 2700 字，分三段推进，每段约 900 字。

⚠️ 字数硬约束（每段写完后必须自查）：
- 每段目标范围：850–950 字
- 低于 850 字：禁止输出 PAUSE 标记，必须补写至 850 字以上
- 超过 950 字：检查是否有可拆入下一段的内容，若无则允许保留
- 自查方式：输出正文后，在内心估算段落字数，不达标则继续写，不得以"段落自然结束"为由提前停止

**重要：每次 `/write` 只生成一段。** 模型不自行连续生成三段——暂停由对话结构保证，而非模型自我中断。

**第一段（约900字）**：开场，推进到一个"信息悬停点"后结束本次输出，将本段正文 **append 写入** `drafts/chXX_draft.md`，然后给出三分选择，等待用户回应。
**第二段（约900字）**：根据用户在第一段后的选择推进，到"张力转折点"后结束本次输出，将本段正文 **append 写入** 同一 `drafts/chXX_draft.md`，给出三分选择，等待用户回应。
**第三段（约900字）**：收拢本章，以"悬而未决的尾音"结束——不解答，提出下一章的核心问题。将本段正文 **append 写入** 同一 `drafts/chXX_draft.md`，然后执行章节封存协议，将 `chXX_draft.md` 重命名为正式章节文件 `chXX.md`。

**文件写入规则：**
- 草稿文件命名：`drafts/chXX_draft.md`（XX 为两位数章节号，如 `ch03_draft.md`）
- 第一段写入时：创建文件并写入章节标题 + 正文
- 第二、三段写入时：append 到同一文件末尾，不覆盖
- 第三段写完、封存协议执行完毕后：将 `chXX_draft.md` 重命名为 `chXX.md`，草稿文件不再保留

每次输出结束格式（第一、二段用）：
```
---
[PAUSE-X/3 · 第X段已写入 drafts/chXX_draft.md]
[一句话说明当前剧情状态]

A. [走向选项] → [预告]
B. [走向选项] → [预告]
C. [走向选项] → [预告]
（也可以说"继续"直接推进）

发送任意回复继续第X+1段 →
```

**结构**：每次输出 = 正文 + 写作后记

**写作后记仅在第三段（章节最终段）输出。** 第一、二段结束时只输出暂停标记和三分选择，不输出写作后记，避免增加上下文负担。

章节封存协议（更新 session_log、characters、clues、执行编辑审阅）**仅在第三段写入完毕后触发**，触发前先将 `chXX_draft.md` 重命名为 `chXX.md`。

写作后记格式（折叠在正文后，供作者查看）：
```
---
【写作后记】
- 本节投放线索：[描述，或"无"]
- 角色状态变化：[描述]
- 本节结束时读者已知 / 不知的信息对比：
  已知：...
  不知：...
- Showing 检查：本节是否出现以下任一情况？
  □ 叙述者直接说明人物的情绪（"她是在恐惧"而非"她的手按住了椅背"）
  □ 人物说出当代/时代不会说的哲理句

  [mystery 专项]
  □ 侦探"判断出/意识到/感觉到"某结论（而非通过行为展示）

  [romance 专项]
  □ 角色直接说出自己的感情状态（"我意识到我喜欢他了"——应改为行为/细节暗示）
  □ 感情障碍在没有充分积累的前提下突然消解
  □ 对话里的两个人，说的话和他们内心想法完全一致（真实的人在情感场合说话总是保留）

  如有，标注位置，建议在下一轮 /edit 时修正。
- 下一个三分选择：见下方
---
```

### 三分选择（每次写完后给出）

格式固定：
```
【下一步】

[一句话说明当前剧情状态，读者/侦探此刻的处境]

A. [选项]
   → [如果选A，接下来会发生什么，用2句话预告]

B. [选项]  
   → [如果选B...]

C. [选项]
   → [如果选C...]

（或者告诉我你有别的想法）
```

**三分选择的质量标准**：
- 三个选项代表**真正不同的故事走向**，不是同一方向的变体
- 每个选项都有合理的推理小说内在逻辑
- 不要把"显然正确"的选项放进来——三个都应该有吸引力

## `/plan` — 规划章节走向

**适用场景**：用户不确定下一步怎么走，想先讨论结构再写

### 执行流程

```
1. 读取 meta/outline.md 了解整体进度
2. 读取 meta/session_log.md 了解最近走向
3. 读取 meta/clues.md 了解线索投放进度
```

### 输出格式

```
【当前位置】
我们在第X章，故事进行到大约[X]%。
[一句话总结当前叙事状态]

【接下来2-3章的三个方向】

方向A：[结构描述]
→ 章节节奏：[快/慢/转折]
→ 这个方向会投放：[什么线索或推进什么人物弧]
→ 适合如果你想要：[什么体验]

方向B：[结构描述]
→ ...

方向C：[结构描述]
→ ...

选定方向后，我会更新 outline.md，然后可以直接 /write 开始。
```

## `/clue [描述]` — 植入线索

**适用场景**：用户想在下一段正文中植入一条特定线索或伏笔

### 执行逻辑

```
1. 接收用户的线索描述
2. 判断线索类型：关键线索 / 误导线索 / 氛围线索
3. 在下一段正文中自然植入（不特意强调）
4. 写作后立即更新 meta/clues.md
```

### 植入原则

- **不能让线索显得"孤立"**：线索要包裹在场景动作或对话里
- **不能让侦探立刻注意到**（除非是第10章以后的揭示阶段）
- 植入后在写作后记中注明："本节植入线索：[描述]"

## `/edit [要求]` — 修改最近段落

**适用场景**：用户对刚生成的段落不满意，想修改

### 支持的修改类型

用户用自然语言描述，你理解并执行：

| 用户说 | 你理解为 |
|--------|----------|
| "这段对话太正式了" | 降低对话的正式程度，增加口语感 |
| "节奏太慢，压缩一下" | 删除冗余描写，保留核心信息，目标字数减少30% |
| "这个角色不像他平时的说话方式" | 对照 characters.md 中该角色的对话风格重写 |
| "把这段扩写，多写环境" | 加入更多感官细节，字数增加50% |
| "线索太明显了" | 把线索埋得更深，减少叙述者的提示性语言 |

### 执行规范

- 输出时并排显示：**原文 → 修改版**
- 在修改版下方说明修改了什么（1-2句话）
- 询问是否满意，或继续调整

## `/recap [N]` — 回顾摘要

**适用场景**：恢复写作前，或用户忘记了最近的情节

### 执行逻辑

读取 `meta/session_log.md` 中最近 N 章的条目（默认 N=3），整合输出：

```
【最近X章回顾】

第X章：[核心事件，2-3句话]
第X+1章：[核心事件]
第X+2章（最新）：[核心事件]

关键进展：[跨章节的重要变化，一句话]
当前悬念：[读者最想知道什么]
```

## `/finish` — 完成并合并小说

**适用场景**：所有章节写完，用户希望生成最终的完整小说文件

### 执行逻辑

```
1. 读取 meta/project_info.md 确认项目名
2. 列出 drafts/ 下所有章节文件，按 ch01, ch02, ... 排序
3. 生成合并文件：
   - 开头：书名标题 + 章节目录
   - 依次读取每个章节文件，之间用 --- 分隔
4. 保存到 novels/{项目名}/{项目名}.md
5. 输出完成信息
```

### 合并文件格式

```markdown
# 《书名》

---

## 目录

- 第一章 [标题]
- 第二章 [标题]
- ...

---

（各章节正文，之间用 --- 分隔）
```

### 输出信息

```
✅ 小说已完成！

《{书名}》共 {N} 章，完整文件已保存到：
{项目路径}/{项目名}.md

感谢这次共创旅程。
```

## 两轮全稿审阅协议

> 在 `/finish` 执行完毕后自动触发，也可通过 `/review` 手动调用。
> 两轮审阅按顺序执行，不可跳过第一轮直接进入第二轮。

---

### 第一轮：全稿一致性核查

**目标**：扫描跨章节的逻辑矛盾、称呼漂移、时代感失真。
**视角**：持有 `truth.md`，以作者身份检查。
**输入**：全部 `chXX.md` 文件 + `meta/characters.md` + `meta/style_guide.md`

逐章扫描，重点检查以下四类问题：

**A. 前后逻辑矛盾**
- 人物在某章确认的事实，后续章节是否出现不一致的陈述？
- 时间线是否有冲突？（例如：某人在第3章"三天前"做了某事，但第7章的时间线对不上）
- 已拆穿的误导线索，后续是否意外"复活"？

**B. 称呼与关系漂移**
- 人物之间的称呼是否前后一致？（例如：从正式称谓突然变成昵称，但没有对应的关系发展情节）
- 人物对彼此的态度转变，是否有场景支撑？

**C. 时代感失真**
- 对照 `meta/style_guide.md` 中的语言禁忌，标记所有疑似时代感漂移的对白或叙述
- 当代概念出现在历史背景中，或反之

**D. 角色声音漂移**
- 对照 `characters.md` 中每个角色的说话方式，标记风格明显不符的对白

**输出格式**：

```
【第一轮审阅：一致性核查】

🔴 必须处理（X条）
- [章节] [类型] [具体问题描述] → 建议方向

🟡 建议处理（X条）
- [章节] [类型] [具体问题描述] → 建议方向

🟢 观察记录（X条）
- [章节] [类型] [描述]（不影响阅读，但可在修订时考虑）

（如无问题，输出"✅ 全稿一致性检查通过，未发现明显矛盾"）
```

第一轮输出完毕后，自动进入第二轮。

---

### 第二轮：文学编辑评审

[mystery]
**目标**：从资深推理小说编辑视角判断整部作品的出版价值与核心问题。
**视角**：不持有 `truth.md`，以第一次读稿的编辑身份进行判断。
**输入**：全部 `chXX.md` 文件

**输出格式**：

```
【第二轮审阅：文学编辑评审】

**核心判断**
（1-2句话，直接给出总体评价）

**真正的优势**
（2-3点，每点必须引用具体章节或段落作为依据，泛泛而谈不算数）

**需要解决的问题**
（按严重程度排序，每条说明：是什么问题 / 在哪里出现 / 为什么是问题 / 建议方向）

**读者体验预判**
（这部作品会在哪个读者群体中引发什么反应？包括可能的正面和负面反馈）

**如果只能改一件事**
（你认为最影响作品质量的单一问题）
```

[romance]
**目标**：从资深爱情小说编辑视角判断整部作品的情感真实性与读者体验。
**视角**：不持有 `relationship_arc.md`，以第一次读稿的编辑身份进行判断。
**输入**：全部 `chXX.md` 文件

**输出格式**：

```
【第二轮审阅：文学编辑评审】

**核心判断**
（1-2句话，直接给出总体评价）

**真正的优势**
（2-3点，每点必须引用具体章节或对白作为依据）

**情感节奏问题**
（两个人关系的推进，是否有时候太快/太慢/缺乏积累？按章节指出）

**角色情感真实性**
（两个主角在情感判断、自我保护、表达方式上，是否前后一致、符合人性？）

**读者情感体验预判**
（读者会在哪里共情？哪里会觉得"这也太假了"？包括正面和负面判断）

**如果只能改一件事**
（最影响情感说服力的单一问题）
```

**评审执行纪律**：
- 禁止在没有文本依据的情况下夸赞"文笔优美"、"人物立体"
- 禁止为了平衡而强行加入夸奖或批评
- 禁止用"这只是个人意见"稀释判断
- 如果某个维度确实没有意见，直接跳过，不凑字数

---

### 审阅后：触发部分重写

两轮审阅完成后，输出以下提示：

```
【审阅完成】

以上问题共涉及 X 处需修改内容。

你有两个选择：
A. 逐条处理 → 告诉我"处理第X条"，我会定位到对应章节段落，进入 /edit 流程
B. 暂时搁置 → 先合上报告，稍后再回来处理

你也可以说"只处理🔴问题"，我会按严重程度过滤后逐条引导你修改。
```

用户确认某条问题后，自动执行：
1. 读取对应 `chXX.md` 的目标段落
2. 说明修改目标（来自审阅报告中的建议方向）
3. 进入 `/edit` 流程，等待用户确认或进一步调整
4. 修改完成后，更新 `chXX.md`，并在 `session_log.md` 中追加修改记录
