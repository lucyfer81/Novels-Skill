# 写作循环：指令行为定义

## `/write` — 推进剧情

### 执行前准备（必须完成）

```
1. 读取 meta/style_guide.md（仅加载"绝对禁止"和"样板句式"两节）
2. 读取 meta/truth.md（提醒自己不能泄露的信息）
3. 读取 meta/characters.md（本章出场角色）
   ⚠️ 首次出场角色只加载以下字段：
   - 出场前读者已知信息
   - 出场引入方式
   - 身份（仅职业/社会角色）
   完整档案（性格、动机、隐瞒的事）须在该角色二次出场后才解锁。
4. 读取 meta/clues.md（已投放 / 待投放线索）
5. 读取上一章最后500字（确保衔接）
6. 读取 meta/outline.md 中本章的计划节点
```

### 写作前行为预检（凶杀/高风险场景专用）

在涉及凶杀或高风险对抗的场景前，先用一句话回答：
"[受害者]此时的信息量是[X]，他/她的求生本能和处事逻辑，会让他/她做出什么行为？"
如果计划中的剧情与这个答案冲突，必须调整触发条件（让场景在更高的张力点爆发），而不是降低人物智识。

### 写作规范

**字数与节奏**：每章目标约 2700 字，分三段推进。

**第一段（约900字）**：开场，推进到一个"信息悬停点"后强制暂停，给出三分选择。
**第二段（约900字）**：根据用户选择推进，到"张力转折点"后再次暂停，给出三分选择。
**第三段（约900字）**：收拢本章，以"悬而未决的尾音"结束——不解答，提出下一章的核心问题。

每次暂停格式：
```
---
【第X/3段写完】
[一句话说明当前剧情状态]

A. [走向选项] → [预告]
B. [走向选项] → [预告]
C. [走向选项] → [预告]
（也可以说"继续"直接推进）
```

**结构**：每次输出 = 正文 + 写作后记

写作后记格式（折叠在正文后，供作者查看）：
```
---
【写作后记】
- 本节投放线索：[描述，或"无"]
- 角色状态变化：[描述]
- 本节结束时读者已知 / 不知的信息对比：
  已知：...
  不知：...
- Showing 检查：本节是否出现以下任一情况？
  □ 侦探"判断出/意识到/感觉到"某结论（而非通过行为展示）
  □ 叙述者直接说明人物的情绪（"她是在恐惧"而非"她的手按住了椅背"）
  □ 人物说出当代/时代不会说的哲理句
  如有，标注位置，建议在下一轮 /edit 时修正。
- 下一个三分选择：见下方
---
```

### 三分选择（每次写完后给出）

格式固定：
```
【下一步】

[一句话说明当前剧情状态，读者/侦探此刻的处境]

A. [选项]
   → [如果选A，接下来会发生什么，用2句话预告]

B. [选项]  
   → [如果选B...]

C. [选项]
   → [如果选C...]

（或者告诉我你有别的想法）
```

**三分选择的质量标准**：
- 三个选项代表**真正不同的故事走向**，不是同一方向的变体
- 每个选项都有合理的推理小说内在逻辑
- 不要把"显然正确"的选项放进来——三个都应该有吸引力

## `/plan` — 规划章节走向

**适用场景**：用户不确定下一步怎么走，想先讨论结构再写

### 执行流程

```
1. 读取 meta/outline.md 了解整体进度
2. 读取 meta/session_log.md 了解最近走向
3. 读取 meta/clues.md 了解线索投放进度
```

### 输出格式

```
【当前位置】
我们在第X章，故事进行到大约[X]%。
[一句话总结当前叙事状态]

【接下来2-3章的三个方向】

方向A：[结构描述]
→ 章节节奏：[快/慢/转折]
→ 这个方向会投放：[什么线索或推进什么人物弧]
→ 适合如果你想要：[什么体验]

方向B：[结构描述]
→ ...

方向C：[结构描述]
→ ...

选定方向后，我会更新 outline.md，然后可以直接 /write 开始。
```

## `/status` — 查看当前状态

**适用场景**：用户想了解项目当前状态，或恢复写作前的快速回顾

### 输出格式

```
【《书名》 状态报告】

📍 进度：第X章 / 预计共X章（约X%）

👥 核心角色状态
- [角色名]：[当前处境，一句话]
- [角色名]：[当前处境]

🔍 线索地图
✅ 已投放（X条）：[简要列表]
⏳ 待投放（X条）：[简要列表]
❌ 误导线索（X条）：[简要列表，注明是否已被拆穿]

🧵 未解伏笔
- [伏笔描述] → 计划在第X章揭示

📊 节奏评估
[正常推进 / 建议加速 / 建议放慢呼吸]

📝 编辑待处理事项
- 🔴 未处理问题：[X条，或"无"]
- 🟡 待处理问题：[X条，或"无"]
```

## `/clue [描述]` — 植入线索

**适用场景**：用户想在下一段正文中植入一条特定线索或伏笔

### 执行逻辑

```
1. 接收用户的线索描述
2. 判断线索类型：关键线索 / 误导线索 / 氛围线索
3. 在下一段正文中自然植入（不特意强调）
4. 写作后立即更新 meta/clues.md
```

### 植入原则

- **不能让线索显得"孤立"**：线索要包裹在场景动作或对话里
- **不能让侦探立刻注意到**（除非是第10章以后的揭示阶段）
- 植入后在写作后记中注明："本节植入线索：[描述]"

## `/edit [要求]` — 修改最近段落

**适用场景**：用户对刚生成的段落不满意，想修改

### 支持的修改类型

用户用自然语言描述，你理解并执行：

| 用户说 | 你理解为 |
|--------|----------|
| "这段对话太正式了" | 降低对话的正式程度，增加口语感 |
| "节奏太慢，压缩一下" | 删除冗余描写，保留核心信息，目标字数减少30% |
| "这个角色不像他平时的说话方式" | 对照 characters.md 中该角色的对话风格重写 |
| "把这段扩写，多写环境" | 加入更多感官细节，字数增加50% |
| "线索太明显了" | 把线索埋得更深，减少叙述者的提示性语言 |

### 执行规范

- 输出时并排显示：**原文 → 修改版**
- 在修改版下方说明修改了什么（1-2句话）
- 询问是否满意，或继续调整

## `/recap [N]` — 回顾摘要

**适用场景**：恢复写作前，或用户忘记了最近的情节

### 执行逻辑

读取 `meta/session_log.md` 中最近 N 章的条目（默认 N=3），整合输出：

```
【最近X章回顾】

第X章：[核心事件，2-3句话]
第X+1章：[核心事件]
第X+2章（最新）：[核心事件]

关键进展：[跨章节的重要变化，一句话]
当前悬念：[读者最想知道什么]
```

---

## 章节摘要日志格式（session_log.md）

每章完成后，追加以下格式条目：

```markdown
## 第X章 摘要
日期：YYYY-MM-DD

**核心事件**：[发生了什么，100字以内]

**角色变化**：
- [角色名]：[状态变化]

**本章投放**：
- 线索：[描述，或"无"]
- 伏笔：[描述，或"无"]

**信息状态**：
- 读者此刻知道：[关键信息]
- 读者此刻不知道：[关键悬念]

**下章切入点**：[建议的开场场景或起始状态]
```

## `/finish` — 完成并合并小说

**适用场景**：所有章节写完，用户希望生成最终的完整小说文件

### 执行逻辑

```
1. 读取 meta/project_info.md 确认项目名
2. 列出 drafts/ 下所有章节文件，按 ch01, ch02, ... 排序
3. 生成合并文件：
   - 开头：书名标题 + 章节目录
   - 依次读取每个章节文件，之间用 --- 分隔
4. 保存到 novels/{项目名}/{项目名}.md
5. 输出完成信息
```

### 合并文件格式

```markdown
# 《书名》

---

## 目录

- 第一章 [标题]
- 第二章 [标题]
- ...

---

（各章节正文，之间用 --- 分隔）
```

### 输出信息

```
✅ 小说已完成！

《{书名}》共 {N} 章，完整文件已保存到：
{项目路径}/{项目名}.md

感谢这次共创旅程。
```
