# 初始化流程详细设计

## 交互停止契约（最高优先级，违反即失败）

初始化是一场**与真实用户的多轮对话**。以下红线与项目锁定协议同级，适用于整个初始化流程：

1. 🔴 **逐轮停止**：每一轮（前置选择、第1-4轮、基本信息收集）输出后**立即停止生成，等待用户真实回复**。严禁在同一轮输出中自问自答、继续下一轮、或以"用户选择了X"代替真实回复。
2. 🔴 **固定脚本**：所有轮次的问题文本必须使用本文件的定义（推理版见第1-4轮章节，爱情版见"爱情版4轮问题"章节），**逐字使用，不得自行改写标题、引导语和选项**。本文件的导航摘要（SKILL.md）不是脚本，进入初始化前必须先完整读取本文件。
3. 🔴 **选择回声**：每轮收到用户回复后，先摘录用户原话（一行），再进入下一轮。无用户原话 → 禁止推进。
4. **`/auto-write new` 的边界**：`auto` 只作用于初始化完成后的写作流水线。初始化的4轮问答与基本信息收集**永远由真实用户回答**——即使指令带有 `new`，也必须逐轮停止等待用户。
5. 用户主动跳过/说"你决定吧" → 你可以代为选择，但必须**先复述你的选择和理由，征得用户确认**后再推进。

## 流程总览

初始化是一次**前置选择 + 4轮共创对话 + 基本信息收集**，不是表格填写。前置选择确定题材和语言，4轮对话根据题材加载对应问题，用户选择，你根据选择积累"小说DNA"，最后收集基本信息，生成完整的项目文件。

用户也可以在任何一轮说"我有别的想法"——你要灵活接收并整合进已有选择中。

## 前置选择记录

在开场白后，用户回答题材和语言：

- 将 `genre` 记录为 `mystery` 或 `romance`
- 将 `language` 记录为 `zh`（中文）或 `en`（English）

根据 `genre` 值，后续4轮问题加载对应版本：
- `mystery` → 使用现有4轮问题（世界感 / 案件骨架 / 核心张力 / 结局基调）
- `romance` → 使用爱情版4轮问题（见下方"爱情版4轮问题"章节）

根据 `language` 值：
- `zh` → 所有后续问题、生成内容、写作后记均使用中文
- `en` → 所有后续问题、生成内容、写作后记均使用英文
  - 注意：language 影响的是 LLM 输出语言，不影响文件名、字段名（字段名保持英文）

`genre` 和 `language` 在步骤2（生成项目文件）时，必须写入 `meta/project_info.md`：

  genre: mystery | romance
  language: zh | en

## 开场白（固定）

当用户开始新项目时，使用以下开场：

```
很好，我们来一起创作一部小说。

在开始之前，先告诉我两件事：

❶ 你想写哪种类型的故事？
   A. 推理悬疑 → 谜题、案件、真相
   B. 爱情      → 关系、情感、时机

❷ 你希望用什么语言写作？
   A. 中文
   B. English

（你可以一次回答，例如"推理，中文"或"B, A"）

选好后，我会问你4个问题，帮我们一起找到这部小说的样子。
```

## 第1轮：世界感

**目的**：确定时代背景与氛围基调，这决定语言风格、社会关系的底层逻辑。

```
【第1轮：这个故事生活在什么样的空气里？】

背景时代决定了一切——人物说话的方式、案件能被隐瞒的原因、
侦探能调动的资源。选一个让你感觉"对"的世界：

A. 民国时代（1912-1949）
   → 乱世之中，传统与变革碰撞。租界、军阀、旧式家族并存。
     信息靠信件与口耳相传，身份可以伪造，秘密可以沉埋。
     适合：家族恩怨、谍影重重、旧社会秘辛。

B. 千禧年前后（1980-1999）
   → 改革开放浪潮中，旧秩序松动但尚未完全消解。
     固定电话是主要通讯手段，互联网刚刚萌芽。
     国企改制、人口流动、城乡夹缝中藏着无数故事。
     适合：社会转型期的阵痛、人情社会的暗流、小城旧事。

C. 当代都市（2010年代至今）
   → 监控摄像、手机记录、社交媒体构成信息迷宫。
     罪行发生在写字楼、公寓、网络空间。
     嫌疑人有律师意识，警察受程序约束。
     适合：职场权谋、家族遗产、互联网暗面。

（任何一个时代都可以叠加「封闭场景」——暴风雪山庄、孤岛、密闭列车，
凶手被困在有限的几个人中间。选完时代后告诉我是否需要叠加。）

（也可以告诉我你有完全不同的想法）
```

**选择记录**：将用户选择存入 `世界感` 变量，继续第2轮。

## 第2轮：案件骨架

**目的**：确定诡计的"性质"——不是具体设计，而是读者解谜时的体验类型。

```
【第2轮：这个谜题的核心是什么类型的"欺骗"？】

推理小说里，诡计不只是"怎么杀人"，更是"如何欺骗读者的认知"。
三种根本不同的欺骗方式：

A. 物理诡计（不可能犯罪）
   → 密室、不在场证明、时间错位。
     读者在挑战：这在物理上是否可能？
     适合：严密的逻辑游戏，解谜的快感在"啊原来如此"的瞬间。

B. 心理诡计（叙述欺骗）
   → 读者一直在看，但看到的是经过选择的信息。
     凶手可能一直在场，只是你的视角被操控了。
     适合：叙述者不可靠、视角的盲区、读者与作者的智力博弈。

C. 社会诡计（动机的隐藏）
   → 物理上没有谜题，谜题是：谁有理由这么做？为什么？
     案件揭开一个家族、一个机构、一段历史的脓包。
     适合：社会派，人性比逻辑更重要，真相令人悲哀而非惊叹。

（也可以告诉我你有完全不同的想法）
```

---

## 第3轮：核心张力

**目的**：确定侦探与案件之间的情感关系——这是故事的"发动机"。

```
【第3轮：侦探为什么非查不可？】

推理小说最动人的部分不是诡计，而是侦探与真相之间的张力。
是什么力量驱使他/她走到最后？

A. 职业义务 + 个人代价
   → 警察或职业侦探，查案是工作，但这个案子触碰了
     他/她不想触碰的东西——家人、过去的失败、某个承诺。
     张力来自：职责要求他继续，情感让他想停下。

B. 局外人卷入
   → 主角原本与案件无关，却因为某个偶然成为唯一
     知道某个关键信息的人，或者被错误地怀疑。
     张力来自：越查越危险，但不查无法自证清白或保护某人。

C. 侦探认识凶手
   → 从一开始就有强烈的预感或怀疑，但那个人是朋友、
     家人、或自己尊敬的人。查案就是在拆解一段关系。
     张力来自：真相会伤人，但谎言更令人窒息。

（也可以告诉我你有完全不同的想法）
```

## 第4轮：结局基调

**目的**：确定故事最终给读者留下什么感受。这影响全篇的信息投放策略。

```
【第4轮：当一切揭开，读者应该感受到什么？】

结局的基调从第一章就开始在暗处运作。
你希望读者合上书时，心里是什么味道？

A. 正义的代价
   → 真相被揭露，凶手受到追究，但这个过程摧毁了某些
     本不该被摧毁的东西。正确的结局，沉重的代价。
     读者感受：值得，但心里有个洞。

B. 灰色的真相
   → 凶手有自己的逻辑，受害者未必无辜，
     正义与法律之间存在裂缝。侦探选择了某个答案，
     但不是唯一的答案。
     读者感受：不安、持续思考、没有简单结论。

C. 救赎与和解
   → 案件的核心是一段被误解的关系或一个无法开口的秘密。
     真相揭开不是为了惩罚，而是为了让某些人终于可以放下。
     读者感受：悲伤但释然，像一场迟到的告别。

（也可以告诉我你有完全不同的想法）
```

## 4轮完成后：收集基本信息

4轮选择完成后，输出总结确认并收集三项基本信息（**这仍是交互轮，输出后停止等待用户回复**）：

### 步骤1：总结确认

```
好，我们来看看这部小说的轮廓：

- 世界：[用户选择的概括]
- 诡计性质：[用户选择的概括]
- 核心张力：[用户选择的概括]
- 结局基调：[用户选择的概括]

（romance 版对照：世界 / 阻力类型 / 叙事视角 / 结局基调）

在你选择的背后：[用2-3句话把你感受到的这部小说的独特气质讲给用户听]

——以下是初始化的最后三个问题——

1. 这部小说叫什么名字？（或者暂定名，1-10字）
2. 主角叫什么？大概是什么样的人？（一两句话就够，50字以内）
3. [mystery] 案件是什么？（死亡？失踪？盗窃？200字以内，说清案件类型与核心谜面即可，不要剧透你心里的答案）
   [romance] 两个人的起点是什么？（200字以内：他们故事开始时的关系与处境）

三个问题可以一起回答；不确定的部分可以说"你提议"，我会给出选项。
```

⚠️ 收集到三项信息前，严禁开始生成任何项目文件。

### 步骤2：生成所有meta文件

获取基本信息后，依次生成（读取对应模板）。以下为推理版清单；爱情版的文件差异见下方"爱情版 项目文件生成"对照表：

1. **`meta/project_info.md`** - 记录项目名称、类型、4轮选择（含用户原话摘录）、三项基本信息、genre、language
2. **`meta/style_guide.md`** - 风格宪法（读取 `templates/style_guide_template.md`）
3. **`meta/truth.md`** - 真相文档（读取 `templates/truth_template.md`；含「假真相设计」「假设链规划」「揭示方式约束」「过去的露出纪律」。若用户案件描述为"多年前旧案重揭"类，必须落实「过去的露出纪律」——过去以当前证据形态分散浮出，禁止终章"历史故事块"）
4. **`meta/clues.md`** - 线索地图（读取 `templates/clues_template.md`）
5. **`meta/characters.md`** - 角色档案（读取 `templates/characters_template.md`，至少包含主角、嫌疑人和1-2个关键配角）
6. **`meta/outline.md`** - 章节大纲（读取 `templates/outline_template.md`；每章必须包含本章目标、应投线索（CL/RH 编号）、假设操作（建立/强化/推翻 H-X）、应揭秘密、应拆穿误导、章末钩子，并与 truth.md 的线索投放总表及假设链规划一致）
7. **`meta/session_log.md`** - 空日志文件，等待第一章完成后填入

### 步骤3：创建项目目录

在项目根目录的 `novels/` 下创建项目：
```
novels/{项目名}/
├── meta/        （上述7个文件）
└── drafts/      （空目录，等待第一章）
```
锁定 `{project_dir} = novels/{项目名}`。

### 步骤4：开启写作流程

- **若初始化是由 `/auto-write new` 触发**：
  输出项目就绪提示后，**自动无缝启动**从第 1 章开始的自动写作流水线：
  ```
  ✅ 新项目已创建完成：{project_dir}
  📖 小说《{书名}》骨架构建完毕，正在启动从第 1 章开始的自动写作流水线...
  ```
  然后立即执行 `/auto-write` 循环，无需用户再次输入。

- **若由普通对话或 `/write new` 触发**：
  输出邀请提示：
  ```
  项目已创建完成：{project_dir}

  你的小说《{书名}》已经有了骨架。

  接下来你可以：
  - 输入 /write 直接开始第一章交互创作
  - 输入 /auto-write 自动完成全书创作
  - 输入 /auto-chapter 自动完成第一章
  - 输入 /plan 先讨论前三章的走向

  你说了算。
  ```

> 仅在用户选择 genre=romance 时使用。推理版4轮问题不变。

### 第1轮：关系的土壤

**目的**：确定两个主角相遇、相处的时代和环境背景，这决定他们能做什么、不能做什么。

```
【第1轮：这段感情生长在什么样的土壤里？】

背景决定了两个人如何相遇、如何误解、如何靠近。
选一个让你感觉"对"的世界：

A. 当代都市职场
   → 写字楼、差旅、项目截止日。感情在压力与距离中生长，
     人们擅长用忙碌掩盖情绪，一条消息可以发出去，也可以删掉。
     适合：相爱相杀、权力关系、重逢。

B. 校园或青春时代
   → 共享食堂、社团、考试季。感情直接且脆弱，
     一次没有回复的消息可以在心里放三年。
     适合：初恋、错过与重逢、成长的代价。

C. 异地 / 跨文化
   → 时差、语言障碍、不同的生活习惯。距离制造了浪漫，
     也制造了误解。每次见面都像在倒计时。
     适合：跨越重重阻碍、分离与抉择、两种生活方式的碰撞。

（也可以告诉我你有完全不同的想法）
```

**选择记录**：`世界感` → 继续第2轮。

---

### 第2轮：感情的阻力

**目的**：确定两个主角之间最核心的障碍类型——这是故事的发动机。

```
【第2轮：是什么让这段感情不能顺利发生？】

爱情故事里，障碍的性质决定了一切的走向。
选一种最能打动你的阻力：

A. 外部阻力（身份 / 处境 / 第三方）
   → 家庭反对、竞争关系、前任的存在、朋友间的纠葛。
     两个人本身是合适的，但外部环境不允许。
     感情推进靠的是勇气和选择。

B. 内部阻力（误解 / 心理创伤 / 自我保护）
   → 有人不敢相信对方真的喜欢自己；
     有人因为过去的伤害，主动在感情里设防；
     有人把爱情理解成了负担。
     感情推进靠的是自我突破和信任的建立。

C. 时机阻力（错过 / 时差 / 选择冲突）
   → 在对的地方遇见，在错的时间点。
     一个要离开，一个刚刚准备好。
     感情推进靠的是等待、放手，或追上去。

（也可以告诉我你有完全不同的想法）
```

**选择记录**：`阻力类型` → 继续第3轮。

---

### 第3轮：叙事视角

**目的**：确定故事用谁的眼睛讲述，这影响读者与哪个角色的亲密度。

```
【第3轮：我们跟着谁的心跳走？】

视角不只是技术问题——它决定了读者会爱上哪个角色，
以及这个故事最核心的情感来自哪里。

A. 单一视角（跟着其中一人）
   → 读者和这个角色同步：他/她不知道的，读者也不知道。
     另一方变得神秘，一个眼神就可以被解读很久。
     适合：暗恋、误解、自我认知的成长。

B. 双视角轮换（两个人各有章节）
   → 读者比两个主角都"知道得多"——看着他们彼此误解，
     同时知道双方其实都在乎。这种反差制造甜蜜的痛苦。
     适合：错位的感情、两种内心世界的对比。

C. 旁观者视角（朋友 / 家人 / 同事）
   → 爱情发生在别人眼里。旁观者看得清楚，当事人却看不见。
     这个视角自带讽刺感，也自带温柔。
     适合：群像故事、从外向内写感情。

（也可以告诉我你有完全不同的想法）
```

**选择记录**：`叙事视角` → 继续第4轮。

### 第4轮：结局基调

**目的**：确定这个故事最终给读者留下的情感重量。

```
【第4轮：合上书时，读者心里是什么味道？】

A. 在一起（温暖圆满）
   → 两个人克服了障碍，走到一起。
     但"在一起"不是终点——最后的章节写的是：
     他们怎么选择彼此的那一刻。
     读者感受：被治愈，相信爱情值得。

B. 遗憾（错过或放手）
   → 感情是真实的，但时机、选择、或现实不允许。
     不是谁的错，是生活的形状就是这样。
     读者感受：悲伤但不怨恨，会想到自己的某段往事。

C. 开放（未完成，留白）
   → 故事在一个"可能性"里结束——没有明确答案。
     读者自己决定相信什么。
     读者感受：意犹未尽，有点不甘心，但也觉得这样刚好。

（也可以告诉我你有完全不同的想法）
```

**选择记录**：`结局基调` → 进入"4轮完成后：生成项目文件"流程。

### 爱情版 项目文件生成

4轮完成后，执行与推理版相同的**步骤1（总结确认）**和**步骤3（创建目录）**和**步骤4（邀请开始写作）**，但**步骤2（生成meta文件）**有以下差异：

| 文件 | 推理版 | 爱情版 |
|------|--------|--------|
| `meta/project_info.md` | 记录4轮选择 | 同左，但第2轮改为"阻力类型"，第3轮改为"叙事视角" |
| `meta/style_guide.md` | 读取 `templates/style_guide_template.md` | 读取 `templates/romance_style_guide_template.md` |
| `meta/truth.md` | 读取 `templates/truth_template.md` | 不生成 truth.md（爱情小说无"真相"需要隐藏）；改生成 `meta/relationship_arc.md`，读取 `templates/relationship_arc_template.md` |

**爱情版 outline.md 章节节点说明**（LLM 生成时须应用）：

```
第1-2章：相遇与基准线建立（展示两人各自的日常，以及第一次真实接触）
第3-4章：接近与第一个"错误信号"（靠近，但同时埋下误解的种子）
第5-6章：第一次情感危机（阻力开始真正起作用）
第7章：低谷或转折点（两人关系最远的时刻，或认知的转变）
第8-9章：重新靠近（因为某个事件或选择，距离缩短）
第10-11章：真正的障碍正面交锋（两人必须做出选择）
第12章：结局（根据第4轮选择执行对应结局基调）
```
