# 初始化流程详细设计

## 交互停止契约（最高优先级，违反即失败）

初始化是一场**与真实用户的多轮对话**。以下红线与项目锁定协议同级，适用于整个初始化流程：

1. 🔴 **逐轮停止**：每一轮（前置选择、题材共创各轮、基本信息收集）输出后**立即停止生成，等待用户真实回复**。严禁在同一轮输出中自问自答、继续下一轮、或以"用户选择了X"代替真实回复。
2. 🔴 **固定脚本**：所有轮次的问题文本必须使用脚本定义（题材共创问题见 `references/genres/{genre}/init.md`），**逐字使用，不得自行改写标题、引导语和选项**。本文件的导航摘要（SKILL.md）不是脚本，进入初始化前必须先完整读取本文件与题材包 init.md。
3. 🔴 **选择回声**：每轮收到用户回复后，先摘录用户原话（一行），再进入下一轮。无用户原话 → 禁止推进。
4. **`/auto-write new` 的边界**：`auto` 只作用于初始化完成后的写作流水线。初始化的各轮问答与基本信息收集**永远由真实用户回答**——即使指令带有 `new`，也必须逐轮停止等待用户。
5. 用户主动跳过/说"你决定吧" → 你可以代为选择，但必须**先复述你的选择和理由，征得用户确认**后再推进。

## 流程总览

初始化是一次**前置选择 + 题材共创对话 + 基本信息收集**，不是表格填写。前置选择确定题材和语言，共创对话（轮数与问题脚本由题材包 init.md 定义）根据题材加载题材包的问题脚本，用户选择，你根据选择积累"小说DNA"，最后收集基本信息，按题材包的文件生成清单生成完整的项目文件。

用户也可以在任何一轮说"我有别的想法"——你要灵活接收并整合进已有选择中。

---

## 前置选择记录

在开场白后，用户回答题材和语言：

- 将 `genre` 记录为题材包 id（合法取值以 `references/genres/_registry.md` 登记为准）
- 将 `language` 记录为 `zh`（中文）或 `en`（English）

根据 `genre` 值：
- 🔴 完整读取 `references/genres/{genre}/manifest.md`（槽位解析）与 `references/genres/{genre}/init.md`（各轮问题脚本、基本信息文案、文件生成清单、账本登记口径）——只加载当前题材的题材包，严禁读取其他题材的文件

根据 `language` 值：
- `zh` → 所有后续问题、生成内容、写作后记均使用中文
- `en` → 所有后续问题、生成内容、写作后记均使用英文
  - 注意：language 影响的是 LLM 输出语言，不影响文件名、字段名（字段名保持英文）

`genre` 和 `language` 在步骤2（生成项目文件）时，必须写入 `meta/project_info.md`：

  genre: {题材id}
  language: zh | en

## 开场白（固定）

当用户开始新项目时，使用以下开场（题材选项行由 `references/genres/_registry.md` 按注册顺序生成，字母依序分配）：

```
很好，我们来一起创作一部小说。

在开始之前，先告诉我两件事：

❶ 你想写哪种类型的故事？
{逐行注入 _registry.md 各题材：A. {显示名} → {开场白选项文案}}

❷ 你希望用什么语言写作？
   A. 中文
   B. English

（你可以一次回答，例如"A, A"或直接说题材名）

选好后，我会问你几个问题，帮我们一起找到这部小说的样子。
```

---

## 题材共创对话（各轮）

前置选择完成后，🔴 打开 `references/genres/{genre}/init.md`，**逐字使用**其中的全部轮次问题脚本：

- 每轮结构：标题 / 引导语 / 若干选项（各附2-3句预告，数目由脚本定义）/ "（也可以告诉我你有完全不同的想法）"
- 每轮收到回复后摘录用户原话（选择回声），按 init.md 中该轮的**选择记录**说明存入变量，进入下一轮
- 全部轮次完成后，进入"各轮完成后：收集基本信息"

---

## 各轮完成后：收集基本信息

各轮选择完成后，输出总结确认并收集三项基本信息（**这仍是交互轮，输出后停止等待用户回复**）：

### 步骤1：总结确认

```
好，我们来看看这部小说的轮廓：

- {按题材包 init.md「总结确认的各轮标签」逐项对照，如：世界 / 核心性质 / 核心张力 / 结局基调}
  每项填入[用户选择的概括]

在你选择的背后：[用2-3句话把你感受到的这部小说的独特气质讲给用户听]

——以下是初始化的最后三个问题——

1. 这部小说叫什么名字？（或者暂定名，1-10字）
2. 主角叫什么？大概是什么样的人？（一两句话就够，50字以内）
3. {题材包 init.md「基本信息收集：第3问文案」，如核心起点问题}

三个问题可以一起回答；不确定的部分可以说"你提议"，我会给出选项。
```

⚠️ 收集到三项信息前，严禁开始生成任何项目文件。

### 步骤2：跨项目查重（账本核对）

读取 `novels/_ledger.md`（跨项目创作账本；文件不存在则跳过核对，直接进入步骤3）。将用户刚给出的核心起点描述（第3问）与账本中**同题材**各行的「核心悬念」「标志性装置」对比：

- **高度同构**（同一核心装置骨架 / 同一不可能事件 / 同一关系困境模板）→ 暂停生成，向用户列出碰撞行（书名 + 核心悬念一行），说明"本项目与《X》（同题材）共享同一核心骨架"，给出 2-3 个差异化方向（换标志性装置 / 换核心悬念的性质 / 换核心张力），待用户确认差异化后再继续
- **无碰撞**，或用户已确认差异化 → 进入步骤3

⚠️ 本步骤只读取账本这一份文件，严禁借此扫描其他项目目录（隔离红线见 SKILL.md）。

### 步骤3：生成所有meta文件

获取基本信息（并通过账本核对）后，🔴 按 `references/genres/{genre}/init.md` 的「项目文件生成清单」依次生成（模板路径相对于该题材包 `templates/` 目录）。通用要求：

1. **`meta/project_info.md`** - 记录项目名称、类型、各轮选择（含用户原话摘录）、三项基本信息、genre、language
2. 其余文件（style_guide / core_doc / signal_doc / characters / outline / session_log）- 按清单指定的模板与题材要求生成
3. **`meta/session_log.md`** - 空日志文件，等待第一章完成后填入

### 步骤4：创建项目目录并登记账本

在项目根目录的 `novels/` 下创建项目：
```
novels/{项目名}/
├── meta/        （上述全部文件）
└── drafts/      （空目录，等待第一章）
```
锁定 `{project_dir} = novels/{项目名}`。

随后在 `novels/_ledger.md` 末尾**追加本项目一行**（文件不存在则先创建表头）：

```
| 书名 | genre | 背景/时代 | 核心悬念（一句话） | 标志性装置 | 状态 |
```

- 「核心悬念」「标志性装置」的取材口径按题材包 init.md 的账本登记说明填写；该题材未定义口径的，填最接近核心骨架的两句话
- 只追加本项目行，状态列填"进行中"；严禁改写、删除其他项目的行

### 步骤5：开启写作流程

- **若初始化是由 `/auto-write new` 触发**：
  输出项目就绪提示后，**自动无缝启动**从第 1 章开始的自动写作流水线：
  ```
  ✅ 新项目已创建完成：{project_dir}
  📖 小说《{书名}》骨架构建完毕，正在启动从第 1 章开始的自动写作流水线...
  ```
  然后立即执行 `/auto-write` 循环，无需用户再次输入。

- **若由普通对话或 `/write new` 触发**：
  输出邀请提示：
  ```
  项目已创建完成：{project_dir}

  你的小说《{书名}》已经有了骨架。

  接下来你可以：
  - 输入 /write 直接开始第一章交互创作
  - 输入 /auto-write 自动完成全书创作
  - 输入 /auto-chapter 自动完成第一章
  - 输入 /plan 先讨论前三章的走向

  你说了算。
  ```
